# 卸了 / 关了，Cursor 里却还在按 Mode 换模型

触发词：已经卸载、已经禁用、关掉了、Cursor 里还在生效、还在自动换模型。

**产品状态：不稳定，不建议使用。** 本机要求卸干净后，禁止为了验收再装回去。

## 一句话

不是 Cursor 自带行为。多半是上次没卸干净，或卸干净后被后台自动更新装了回来；当前还开着的 Cursor 对话会继续按旧入口换模型。

## 现象 → 原因 → 动作

1. **以为关掉了，其实还在换**  
   - 原因：`config disable` 只关开关，拦截入口还在。  
   - 动作：要彻底离开，按 [CLI_USAGE_GUIDE.md](../CLI_USAGE_GUIDE.md)「彻底清干净」，不要只跑 disable。

2. **刚跑过彻底卸载，过几分钟又出现**  
   - 原因：当时没退出 Cursor。已开对话里的后台自动更新成功后会再执行一次安装，把拦截入口、配置和开关都写回去（2026-08-28 真机：卸完约 13 分钟整套复现，开关回到开启）。  
   - 动作：先完全退出 Cursor 和相关终端，再按「彻底清干净」卸一次。卸完用新开的登录终端确认命令已不存在。禁止再执行安装来「验证」。

3. **本机文件已经删掉，这条对话却还在换**  
   - 原因：当前进程仍带着旧环境。  
   - 动作：退出 Cursor 再打开；只重开这一条对话不够。

4. **这台电脑卸了，开发机还在 / 只清了一边**  
   - 原因：安装在开发机日常账号下；只查管理员账号会看不见。命令已经不在，数据目录里仍可能留着运行记录。  
   - 动作：两边都按 [CLI_USAGE_GUIDE.md](../CLI_USAGE_GUIDE.md)「彻底清干净」做完。查/卸开发机时用日常账号家目录，不要只查管理员。禁止为了「双机对齐」再装回去。口径见 [MAINTAINER_GUIDE.md](../MAINTAINER_GUIDE.md)「双机对齐」。

5. **卸完 `agent` 找不到，以为 Cursor 被卸掉**  
   - 原因：官方启动文件叫 `cursor-agent`。用户平时敲的 `agent` 往往只来自本工具的包装。拿掉包装后这个名字会消失，官方 Cursor Agent 其实还在。  
   - 动作：在 `~/.local/bin/agent`（及 `cursor-agent`）补回指向当前版本官方启动文件的链接。不要重装自动换模型，也不要去卸/重装 Cursor。已开终端先 `hash -r` 或新开一个再试。

## 禁止

- 不要把「关掉自动切换」说成已经卸载。  
- 不要在未退出的会话里跑状态检查来当卸干净的证据。  
- 不要为了验收、排查或双机对齐再装回本机或开发机。  
- 不要只清这台电脑、漏掉开发机。
